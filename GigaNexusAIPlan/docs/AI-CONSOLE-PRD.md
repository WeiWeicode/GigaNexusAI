# AI 中控台 PRD(草案)

> **狀態:已取消(2026-11-04)。** 使用者決定不另建 AI 中控台;各系統沿用原本專案的 AI 功能,直接呼叫 AI 主機(工作區 `AGENT.md` §5)。NetOps 的做法見 `NetOps/docs/PA-LIVE-PLAN.md` §6。本文件只保留作為紀錄,不再維護。

---

## 1. 背景與目標

各系統開始需要 AI 功能。NetOps 舊版已有問答、分析、翻譯與知識庫向量搜尋,但模型呼叫、提示與向量同步都寫在 NetOps 內;之後其他系統再各做一次,模型設定、用量與紀錄會四散。

因此 AI 功能不在各業務系統內重寫,改由兩個新元件提供:

| 元件 | 用途 |
| --- | --- |
| **AI 中控台(應用)** | 集中管理模型、知識庫、用量與呼叫紀錄的畫面與服務 |
| **AI SDK** | 業務系統接入 AI 的共用套件,不必各自處理模型連線與串流 |

**已確定**:獨立的 SDK 與應用、名稱為 AI 中控台、另開 repo 與資料夾;NetOps 這次接入 Gateway 不改寫 AI 功能。**本文件其餘內容是依現況提出的草案,開工前要確認。**

## 2. 範圍

### 2.1 第一版(草案)

1. 模型服務登記與狀態:問答、embedding、翻譯。
2. SDK:問答與串流、embedding、翻譯。
3. 知識庫向量同步與語意搜尋。
4. 呼叫紀錄與用量:系統、使用者、模型、時間、字數、結果。
5. NetOps 接入,取代舊版 AI(§4)。

### 2.2 不在第一版

- 外部雲端模型;資料不出公司內網。
- 自然語言操作、代替使用者送出動作。
- 各業務系統的業務查證邏輯:仍由各系統提供,例如 NetOps 查防火牆 log。

## 3. 需求草案

### 3.1 AI 中控台

| # | 需求 |
| --- | --- |
| C1 | 查看各模型服務是否可用、目前模型與版本 |
| C2 | 依系統設定可用模型與用量上限 |
| C3 | 查詢呼叫紀錄;預設不存完整提示與回答,是否保存待定(Q5) |
| C4 | 管理知識庫 collection 與同步狀態 |
| C5 | 登入與權限沿用 Gateway:BFF 單一入口、GigaItApp 設定 RBAC |

### 3.2 SDK

| # | 需求 |
| --- | --- |
| S1 | 問答:一般與串流回應、取消、逾時;中斷連線時停止呼叫模型 |
| S2 | embedding 與語意搜尋 |
| S3 | 翻譯 |
| S4 | 明確回報失敗:模型連不上、回答被截斷、降級為關鍵字搜尋都要讓呼叫端知道 |
| S5 | 帶入呼叫系統與使用者身分,供稽核與用量統計;不經手使用者 Token 以外的憑證 |
| S6 | 呼叫端不直連模型或 Qdrant,不保存模型金鑰 |

### 3.3 安全與資料

- 只送完成任務所需的資料;NetOps 維持只送統計與彙整,不送整份原始 log。
- 系統提示與問題字數要有上限。
- 知識庫內容是資料,不可被當成指令放大權限;回答輸出前端時要消毒。
- 機密不入版控,正式環境走 Docker secret。

## 4. 第一個接入方:NetOps

以下功能**留在舊版 IIS**,NetOps 新版不搬移(NetOps `docs/ARCHITECTURE.md` D17),AI 中控台完成後再接入並停用舊版:

| 功能 | 舊版位置 | 使用的服務 |
| --- | --- | --- |
| AI 分析(期間統計) | `POST /ai/analyze`、`GET /ai/context` | vLLM 問答 |
| AI 問答(PA、AD,含 FTP 查證) | `POST /ai/ask`、`server/lib/evidence.js` | vLLM 問答 |
| 整理成知識庫筆記 | `POST /ai/note` | vLLM 問答 |
| 翻譯 | `POST /ai/translate` | vLLM 問答 |
| 語意搜尋與向量同步 | `GET /kb?semantic=`、`POST /kb/vector-sync`、`server/lib/vector.js` | embedding、Qdrant |
| 外部 IP 自動學習 | `/kb/learn-ips`、`server/lib/iplearn.js` | RDAP、DNS、vLLM 問答 |

NetOps 新版持續產生摘要與連線組合統計,知識庫也由新版管理,接入時可直接使用。

現有服務:vLLM `10.10.130.45`(`:8080` 問答、`:8081` embedding)、Qdrant `10.10.130.46`。

## 5. 與平台的關係

- 經 Gateway 接入:SPA 子路徑、`/api/*` 經 BFF、內部 Token。系統代碼、port 開工時向 Gateway 登記(BACKEND-GUIDE §3.3),現在不佔用。
- **串流要先驗證**:Nginx 與 BFF 都有最長 60 秒的閒置逾時,Nginx 預設緩衝。開工第一步要在測試區實測 POST + SSE + heartbeat,失敗就改工作加輪詢。這項驗證原本排在 NetOps B0,已移來此處。
- 甘特圖 W7 已有「AI Gateway(模型路由、配額、稽核)」,範圍與本文件重疊,要合併或劃分(Q1)。
